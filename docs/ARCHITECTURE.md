## 1. What Lootpath is

**One sentence:** Lootpath puts QE Live's gear answers inside World of Warcraft, next to the loot they are about.

**The three promises, on one in-game frame:**
1. **Equip Now** - what you should be wearing right now, from what you own, with one-click equip.
2. **Upgrade Map** - for each gear slot, which dungeon boss or raid boss drops a candidate, and (where QE Live has ranked it) how much better it is.
3. **Vault** - which Great Vault option to take this week.

**The product rule, above every other rule:** **Lootpath never computes a healer value.** Every healing number on screen is QE Live's, transported unchanged from its export. Lootpath's own work is the scanner (gear, bags, bank, vault), the loot map (Encounter Journal walk), matching, and display. No network, no backend, no behaviour in combat, no estimate of its own to fill a gap.

**Who it is for, in order:** the owner (MVP = the owner alone, on one character); then healers generally; DPS via Raidbots/MythicSim output is a later extension of the same import interface, not an MVP goal.

**Why this exists:** the audience's whole gearing loop today is alt-tab: `/simc` in game, paste into QE Live in a browser, read the answer there, alt-tab back and try to remember it at the vault or when a drop appears. QE Live is right about the math; everything around the math happens where the game cannot see it. Mr. Mythical solves this in-game for DPS with a SimulationCraft-trained model; SimulationCraft cannot model healing, so no healer equivalent could be built that way. Lootpath is "Mr. Mythical for healers" with QE Live as the brain.

## 4. QE Live: everything we know (all read from its public source, branch `dev`)

- Repo: github.com/Voulk/QuestionablyEpic. **No licence file** = all rights reserved. Actively pushed (2026-09-02). We read it for understanding and schemas; we copy no code and no data tables.
- **Top Gear exports.** `src/General/Modules/TopGear/Report/TopGearJSONExport.ts`, present since at least 2026-05-20 (last touched by "handle duplicates"). Schema string `"qe-live-droptimizer"`, `version: 1`. Payload:
  ```
  { schema, version, exportedAt (ISO), player: {name, realm, region, spec, gameType: "Retail"|"Classic"},
    contentType, reportId,
    topSet: { score (hardScore), stats (setStats), items: [Item] },
    differentials: [ { scorePercent, hpsDifference, items: [Item], gems: [int] } ] }
  Item = { slot, id, level, bonusIDs: [int], gems: [int], enchant: string, tertiary: string, setId: int, isVault: bool, isExclusive: bool, source: {} }
  ```
  Sign conventions: `scoreDifference` (exported as `scorePercent`) is a percent where **positive means the alternative is worse**; `rawDifference` (exported as `hpsDifference`) is a raw score delta where **negative means the alternative is worse**. ## 5. Data flow (the round-trip)

1. In game: SimulationCraft addon `/simc` (includes equipped, bags, and vault when available) - copy.
2. Browser: run **Top Gear** (M+ by default), Export > **Download JSON**. **On the companion's path this is driven headlessly, and since C-5 the two upgrade checkboxes are set explicitly before Submit** (both off by default), so a vault option and the gear it would replace are valued at the same point on their upgrade tracks; the pair is recorded in `Data/QEVerdict.lua` as `qeSettings`. **Until the fork's PR lands upstream that control exists only on the fork**, so the owner runs it locally (`npm start` in `c:\Code\qe-live-fork`) rather than on questionablyepic.com/live.
3. In game: `/lootpath`, paste the JSON text into the editbox. **The box takes either export** (M3-6): `UI.ImportAny` reads the `schema` string out of the text and hands it to `QEImport` (Top Gear) or `UFImport` (Upgrade Finder); each validates schema, version 1 and Retail for itself and stores its verdict in SavedVariables with its `exportedAt`. A third schema is refused by name, naming both the ones Lootpath reads.
4. `Inventory` scans; `Journal` walks (cached); `Vault` reads; `Match` joins the Top Gear verdict to the inventory by item key, and the Upgrade Map joins the Upgrade Finder verdict to the journal by itemID + item level.
5. Three panels render. Equip Now can equip out of combat.

Constraints that shape it: addons have **no network** and **cannot read files** (hence paste); SavedVariables flush **only on `/reload` or logout**; secret values apply in combat/encounters/M+/PvP (spike-verified they lift out of combat; the guard stays on every read regardless); the bank is readable only while the bank frame is open.

**The companion path (decision 2026-09-07; S-1/S-2 spikes, C-1/C-2 build it):** the same round-trip with no human in the middle. (1) **`/lootpath refresh` takes the `env`, `inventory` and `vault` captures, in that order, and then reloads**, so what reaches disk is the gear the character is wearing now rather than whatever was last captured by hand (C-3, WKE-536; before it refresh only reloaded and the companion valued the newest stored snapshot, which on 2026-09-07 was two days and one spec old). A plain `/reload` still flushes, and still flushes only what was already captured. (2) A Node companion on the owner's PC (`tools/companion/`) watches that file, builds the SimC text profile from Lootpath's own records (mirroring the SimC addon's Unlicense exporter), drives the owner's local fork at localhost:3000 headless to run Top Gear and Upgrade Finder for Dungeon and Raid, and writes the four JSON documents as Lua strings into `Interface\AddOns\Lootpath\Data\QEVerdict.lua` (temp file + rename). (3) `/reload` again: the addon loads that file - it is in the `.toc`, a committed placeholder ships with the addon - and runs each document through the same `QEImport.Parse` as a paste, pins and refusals included. The paste box stays as the manual path. **Both halves are built.** C-1 (WKE-533, PR #27) is `tools/companion/`: it finds the SavedVariables by glob under `WTF\Account\*` (the account name is never written into the repo and never printed), reads them with S-2's reader and builds the profile with S-2's builder (both lifted into `tools/companion/lib/`, so there is one copy of each and not two), drives the fork through Playwright with a persistent browser profile, and writes the chunk temp-file-then-rename. **The addon half (C-2, WKE-534, PR #25):** `ns.Companion` at load, `/lootpath refresh` for both reloads, the source named on screen, and a repo sync that no longer overwrites the companion's file. The file shape it reads is §6's contract, and it is what C-1 must write. This is the Raider.IO pattern: their desktop client writes score databases into the addon folder the same way. Floor: two reloads, zero alt-tabs; nothing in the client can go lower, because SavedVariables reach disk only on reload and addon files load only on reload. **The second reload is free (C-4, WKE-537, PR #32):** every `/reload` writes SavedVariables and the watcher fires on every write, so step (3) used to start a QE Live run of its own over the same gear - 17.7 s and four byte-identical documents, measured on the owner's machine 2026-09-07 21:07. The companion now fingerprints the profile it is about to ask QE Live about (SHA-256 over the profile text with its four volatile header lines removed), remembers in `.state/last-profile.json` the fingerprint of the last verdict it actually wrote, and skips the run when the fingerprint agrees, the remembered path is the file this run would write, and that file is still on disk; it logs one line instead. `--force` runs regardless. The debounce (1500 ms) is untouched and was never the answer: two reloads twenty seconds apart really are two writes and the second must be READ, because the owner may have opened the bank and captured between them - it is the profile, not the write, that decides.

- **2026-09-08 (C-3, WKE-536) - `/lootpath refresh` takes the three snapshots itself, and the reload is what flushes them.** The companion's profile is built from `newestSnapshot(captures.env|inventory|vault)` (`tools/companion/lib/simc-profile.js`), and nothing else in the addon writes gear to SavedVariables, so a refresh that only reloaded shipped whatever the owner had last captured **by hand**: the first real run, 2026-09-07, produced `spec=guardian` from the 09-05 capture, two days and one spec stale, with `region`/`level`/`race` missing because that snapshot predates S-2's reads. `Companion.Refresh()` now runs `env`, `inventory` and `vault` through `ns.RunCapture` in that order and only then calls `ReloadUI`; any refusal is repeated verbatim and stops the reload, so the owner never reloads believing a capture happened. **Why here and nowhere else:** not on `PLAYER_LOGOUT` (the client gives no reliable time there, and a capture at every logout writes SavedVariables nobody asked for); not in the companion (it cannot make the client read anything, only read what was written); not by having `Inventory`/`Vault` write snapshots on every scan (captures are the raw record the tests replay - one writer, or a golden stops meaning what it says). `journal` is excluded on purpose: it is asynchronous, the profile reads none of it, and a reload mid-walk would abandon it. - **2026-09-07 (C-2, WKE-534) - the companion file's shape, and who owns the game's copy of it.** Three things settled while building the addon half.

## 12. Working rules (also in CLAUDE.md, shipped in 514)

Branch per issue (`lp-<n>-<slug>`), PR to `main`, never commit to `main` directly, merge your own PR only when every CI check is green. Read the whole Linear issue including its "Working in this repo" section. Verify the issue's premise against the code before building; a wrong premise is reported in the PR and the right thing is built instead - scaling down is fine, widening is not. Never write a measured figure you did not read from a tool. Every guard proven red. Every client read secret-guarded; nothing in combat; no network; **Lootpath never computes a healer value.** In-game steps are the owner's: write the capture, hand it over as human-required, build against the transcript. Report in every PR: what shipped; premise check; measured figures with the tool; guards and how each went red; CI results; left undone, deliberately. **And update this file**: §0 every session without exception, plus whichever numbered section holds the decision, verified fact, refuted premise, or closed issue. A session that only talked still updates §0 if the talk moved anything.

**One worktree per issue, always** (decision 2026-09-06, after two sessions collided in the shared checkout). Before the first edit: `git worktree add C:\Code\lootpath-<n> -b lp-<n>-<slug> origin/main`, then `fetch-libs.ps1` (and `fetch-annotations.ps1` for the LuaLS gate) inside it, because those directories are gitignored. Work, commit, push and open the PR from there; never edit `C:\Code\lootpath` itself while another session may be active; never `git add -A` in a directory you did not create; remove the worktree after the merge. The exact commands are in CLAUDE.md, and every ai-ready issue's "Working in this repo" section points at them.

**Captures and the Encounter Journal.** Captures only read, with one recorded exception: `capture journal` changes the Adventure Guide's view state (tier, instance, difficulty, loot filter, M+ preview level) because the API has no other way to ask for loot, restores what has a getter, and says what it could not restore (§7, 2026-09-06). Nothing any capture calls acts on the character, its items or its money, and no capture calls what a namespace walk finds.
