# WKE-719: C-vx, the companion names the vault's non-gear rewards once, as extras

## §0
**As of 2026-10-20, afternoon CDT, C-vx (WKE-719 built, PR open on `main` cdab2b1): the companion stops warning once per non-gear vault reward and instead names them all in one info line.**
- **The premise held:** the owner's reset-day run (`Data/companion.log`, 19:46:25Z, captured in `spec/fixtures/captures/Lootpath-20261020-145040.lua`) logged five `warning: the SavedVariables carry no vault reward 180653 / 269862: equipLoc INVTYPE_NON_EQUIP_IGNORE has no SimC slot number ...` lines for rewards that are not gear - the same `week4-compares` inbox entry called this "log noise, not a defect in the rating."
- **What changed:** `tools/companion/lib/simc-profile.js` `vaultRows` now treats any reward whose `equipLoc` is exactly `INVTYPE_NON_EQUIP_IGNORE` as an extra - named (`itemNameFromLink`, or `item <itemID>` with no name) onto a new `extras` list, never pushed onto `missing`. Any other unmapped `equipLoc`, including an absent one, is unchanged: still a real gap in `missing`. `buildProfile` returns the list as `vaultExtras`. `tools/companion/lib/profile.js` `build` turns it into one string or `null` - `vault extras left out, not gear: Mythic Keystone x4, Thalassian Token of Merit` for the fixture - grouped by name in first-seen order, `xN` only above 1. `tools/companion/companion.js` logs it with `log.info`, right after `vault read used:`, only when not null.
- **Verified on the fixture:** `profile.build` over `Lootpath-20261020-145040.lua` now gives no `vault reward` warning, `vaultExtras === 'vault extras left out, not gear: Mythic Keystone x4, Thalassian Token of Merit'`, and unchanged `counts.vault === 2`. A real gap (an unmapped equipLoc that is not the extras' own, e.g. the Sandals reward's `equipLoc` forced to `INVTYPE_QUIVER`) still warns and still drops `counts.vault` - proven red by making the fix over-broad (skip every unmapped equipLoc) and watching that test fail, then restoring.
- **Tests:** added to the existing `test/profile.test.js` and `test/simc-profile.test.js`, no new test file. 50 -> 53 covering tests, all pass; full `node --test` in `tools/companion` 322 pass / 1 skipped -> 325 pass / 1 skipped.
- **Nothing else moved:** the `no generated Great Vault reward` warning, `counts.vault`, the profile text, the verdict, and the `simc-profile.js` CLI's own stderr list (it simply stops listing extras, reading the same `missing`).
- **Open:** none. The addon's `VaultPanel.lua` already treated these as extras and was not touched.
