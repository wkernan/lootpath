**Second rework round (same day, from code review): closed the tracker
contract hole the review found - `lib/attribute.js`'s `onHeal` callback
already called `tracker.countFor(h.dst)` (for `lib/probe.js`), but
`lib/specs/index.js`'s comment, `docs/COMBAT-LOG-WEIGHTS.md` §12 and
`105-restoration-druid.js`'s own comment all said `countFor` was not part of
the contract - a second spec built from the documented contract alone would
throw `TypeError` the moment anyone called `walk()` with an `onHeal`
callback. Added `countFor(target)` to all three statements of the contract,
implemented it on the toy spec (always 0: it tracks no per-target state),
and added a test that walks the registered toy spec with an `onHeal`
callback and asserts its `n` - confirmed red first (today's pre-fix toy spec
had no `countFor`: `TypeError: tracker.countFor is not a function`, exactly
the failure the review predicted), green after.**

`tools/combatlog` keeps everything Restoration Druid-specific in one spec
module behind a small registry, so adding Holy Priest, Mistweaver or any

next, or whether a mastery formula unlike Harmony's (not a stacking-aura
count) needs the tracker/gain contract widened - the ticket's Decision 2
leaves that for whichever spec needs it.**
