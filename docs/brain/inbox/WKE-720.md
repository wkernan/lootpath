# WKE-720: E-7b, a tank's SimC weights measure damage by default

## §0
**As of 2026-10-20, evening CDT, E-7b (WKE-720 built, PR open on `main` bcc6933): `run-scale-factors.js` now defaults a tank's stat weights to DPS (damage), not DTPS (survival).**
- **The premise held**, verified against `tools/simc/run-scale-factors.js`, `tools/simc/lib/intermediate.js` and their tests at `origin/main` `bcc6933`: both defaulted to `'dtps'` (`o.tankValue || 'dtps'` in `run`, `meta.tankValue || 'dtps'` in `build`), so Guardian (104) was survival in Raid and damage (forced via an explicit `--tank-value dps`) in Dungeon.
- **What changed:** both defaults flipped to `'dps'`. `--tank-value dtps` is unchanged as an explicit research option; a tank still always runs both metrics and keeps both in `factors`. The DungeonSlice refusal (`/no DTPS/`) now only fires on an explicit `--tank-value dtps`; with no flag (or explicit `dps`) it records `unmeasured.dtps` instead, as today's explicit `dps` already did. The usage text, the `TANK_VALUE` comment, and `README.md` ("Run it", the metric bullet, "What a tank's value is") were reworded to say damage is the default and name the owner's 2026-10-20 E-7 decision; the historical fixture-generation command list under "The fixtures" was left alone since it records what was actually run to produce the committed reports.
- **Tests:** the default-pinning assertions in `test/tank.test.js` and `test/cli.test.js` were flipped to `dps`; the DungeonSlice refusal test now passes `--tank-value dtps` explicitly, and a new test covers the no-flag case (`value.metric` `dps`, `unmeasured.dtps` matching `/no DTPS/`); `test/writer.test.js`'s Lua-reading assertions (`Raid.bands.all.value.metric`, the CHECK script's `raidMetric`) were flipped to `dps`. 34 -> 35 tests, `cd tools/simc && node --test`: 35 pass, ~0.5s.
- **Red-proof:** reverted both defaults back to `'dtps'` and re-ran `node --test`: 5 of the flipped/new tests failed (`not ok`: the rebuild-from-reports test, the new no-flag DungeonSlice test, the DPS-by-default tank test, and two writer/Lua tests). Restored the fix: all 35 pass again.
- **Full check:** `luacheck . --no-color` (74 files, 0 warnings/errors) and `stylua --check .` from the repo root both pass; no Lua files changed, so busted and the LuaLS gate were skipped, and no other `tools/` directory was touched so no other node suite ran.
- **Open:** none for this ticket. The after-merge step (rebuilding `out/` from the committed reports with no `--tank-value` and confirming both bands read `value.metric = "dps"`) is the coordinator's, per the ticket.
